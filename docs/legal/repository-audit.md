# Codebase audit for Terms of Service and Privacy Policy

**Reviewed:** 26 October 2026. This is an implementation inventory, not a legal compliance audit. File references use repository-relative paths and one-based line numbers.

## Service and account behavior

- The product is a mobile app for browsing Zimbabwean recipes, creating recipes, saving favorites, managing a pantry and shopping list, cooking with step-by-step instructions, and tracking cooking/achievement/leaderboard activity. The repository's feature overview is in [README.md](../../README.md#L5) and [README.md](../../README.md#L15-L30); implementation routes include `app/(tabs)/index.tsx`, `app/(tabs)/explore.tsx`, `app/(tabs)/create.tsx`, `app/recipe/[id].tsx`, `app/cooking/[id].tsx`, `app/achievements.tsx`, and `app/(tabs)/leaderboard.tsx`.
- Users can continue as guests; `app/account-choice.tsx` lines 56–91 presents account creation, login, and guest continuation. `app/account-access.tsx` lines 36–89 supports email/password sign-up and sign-in through Supabase Auth, with a six-character minimum password check and a verification notice when signup returns no session. Signup passes the local profile name as `display_name` (lines 56–63). The app uses persisted Supabase sessions through AsyncStorage in `lib/supabase.ts` lines 23–29.
- The local auth UI has no age check or age declaration. Eligibility/age must be set by the owner and reviewed for target jurisdictions.
- The profile “Log out” action signs out of the current Supabase session and clears device-local account state (`app/(tabs)/profile.tsx`). It does not delete the remote Auth account or remote records. No in-app account deletion or export flow was found; do not promise those controls until they are implemented.

## Data collected, stored, and transmitted

- Local state is persisted in AsyncStorage. The main Zustand store uses key `recipe-app-storage` in `store/useStore.ts`; it includes profile XP, badges and cooking statistics. A separate profile store is persisted under `user-storage` in `stores/userStore.ts`. Cooking and sync state are also persisted in `stores/cookingStore.ts` and `stores/syncStore.ts`.
- Main app state includes favorites, user-created recipes, pantry, shopping list, profile name/avatar/bio, XP/badges/stats, notification preferences, recipe-view history/category scores, locale and theme; see `store/useStore.ts` lines 76–160. Sync sends favorites, shopping list, pantry, onboarding state, profile (excluding local file avatar and push token), view history/category scores, theme, locale, notification preferences, and in-app notifications to `chef_app_state` (`services/syncService.ts` lines 8–27).
- If Supabase is configured and online, the client creates/persists an anonymous Supabase Auth session as needed (`services/syncService.ts`), upserts the app-state JSON, attempts profile and user-recipe sync, and merges saved app state after sign-in. Anonymous data may be tied to the anonymous installation session; the README documents that it cannot be recovered after sign-out/reinstall unless linked through account sign-in. The profile UI now signs out locally and clears that device's local account state; it does not delete the remote Auth account or remote records.
- Supabase Auth receives email, password, and display name on account signup (`app/account-access.tsx` lines 56–63). The public profile migration includes name, avatar URL, bio, XP, level, badges, stats and dietary preferences, but no email column (`supabase/migrations/20261026010000_core_schema.sql` lines 4–17). Recipe records include author, title, description, image URL, category, tags, duration, servings, calories, ingredients and steps (`lines 24–44`).
- Local recipe images and profile avatars can be uploaded to Supabase Storage; recipe image uploads are attempted in `services/syncService.ts` lines 209–237 and avatar uploads in `lines 157–176`. The migrations create public `recipes` and `avatars` buckets and public read/upload/update policies (`supabase/migrations/20261026010000_core_schema.sql` lines 72–94). Treat uploaded recipe and avatar images as publicly accessible when uploaded.
- Public chef/leaderboard records expose chef ID/name, avatar seed/country, XP, level and achievements count (`supabase/migrations/20261026020000_gamification.sql`). The follow-up security migration removes client write policies and revokes the public score-writer RPC (`supabase/migrations/20261026040000_secure_public_writes.sql`). Hosted projects must apply this migration.
- Private app state is restricted by row-level policies to the authenticated Supabase user ID (`supabase/migrations/20261026030000_private_app_state.sql` lines 8–31). The repository cannot establish the hosted Supabase project's actual configuration, region, backups, retention, or operational safeguards.
- Camera and gallery selection are used for ingredient recognition and recipe images (`app/(ai-chef)/index.tsx`, `services/imageCapture.ts` lines 7–44, and `app.json` lines 28–35). `app.json` asks for camera permission for recipe images. The app does not define its own retention schedule for selected images.

## AI and third parties

- AI requests use model router `openrouter/free` through the authenticated `openrouter-completion` Supabase Function (`services/openRouterClient.ts`, `supabase/functions/openrouter-completion/index.ts`). The provider key is read from the server-side `OPENROUTER_API_KEY` secret and is not read from Expo public environment variables. The function requires the security migration's per-account request-limit RPC; both the migration and function must be deployed.
- For ingredient extraction, the app sends a base64 JPEG image to OpenRouter (`services/openRouterClient.ts` lines 22–30; `services/aiRecipes.ts` lines 83–110). Recipe generation sends ingredient names, pantry items and any supplied dietary restrictions, allergies, time limit and servings (`services/aiRecipes.ts` lines 116–146, 174–178). Generated recipes may contain nutrition estimates and safety warnings (`lines 47–63`); there is no code evidence of human review, factual verification, allergy assurance or medical/nutrition validation. AI output must be described as unverified suggestions.
- `openrouter/free` is a routed free model selection, not a code-level guarantee that a specific model or provider is always available or free. The function caps outputs and applies a per-user request limit. Provider-specific processing, logging, training, region and retention settings cannot be established by this repository. OpenRouter says Inputs may be transmitted to model providers and model/provider policies can differ; consult its [Terms](https://openrouter.ai/terms) and [Privacy Policy](https://openrouter.ai/privacy/) before launch.
- Supabase is used for authentication, database, storage, and realtime leaderboard data: `lib/supabase.ts` lines 7–29, `services/syncService.ts`, and `services/leaderboardRealtime.ts`. Hosted project account, region, retention and data processing terms are deployment-specific.
- Expo modules include camera, image picker, notifications, localization, network, store review and app infrastructure (`package.json`; `app.json`). The app requests notification permission on supported physical native builds, schedules local daily and weekly reminders, and can show local notifications for new badges and recipes (`services/notificationService.ts`; `store/useStore.ts`). Remote push delivery is not implemented in this repository.
- The package manifest includes `expo-observe` and `expo-insights` (`package.json`). `app/_layout.tsx` configures Expo Router startup/render/interactive/navigation metrics and filters sensitive route parameters; `ObserveRoot.wrap` instruments the root. `useObserve().markInteractive()` marks onboarding, account-access, home, and recipe-detail screens as interactive. `components/feedback/GlobalErrorBoundary.tsx` reports caught render errors, and Observe's default error handling also records unhandled JavaScript errors unless disabled. `eas.json` production enables source-map upload. Expo Insights is installed for automatic cold-start usage events. These telemetry services are disclosed in `data/legalDocuments.ts` and `docs/privacy/index.html`; review the corresponding Play Data safety answers before releasing. No advertising SDK is configured in the checked application code. Expo/Supabase/OpenRouter infrastructure may also generate provider-side operational logs; precise practices are not established here.
- Recipe browsing logs view history and category scores locally and syncs these fields with private app state (`store/useStore.ts` lines 132–135; `services/syncService.ts` lines 15–27). This is product personalization/learning from interactions, not evidence of model training.

## UGC, ownership, limits, moderation, deletion

- Users can add recipes locally (`store/useStore.ts` lines 304–310); created recipes may later be uploaded to the public Supabase `recipes` table (`services/syncService.ts` lines 198–275). The app allows the user-provided recipe image to accompany the recipe. No explicit content license, moderation process, reporting workflow, or user removal workflow was found. Terms should use a limited license only to the extent needed to host, display and distribute publicly shared recipes/images, and that license must be confirmed with the owner. Ownership statements also require confirmation.
- Public recipe and display-profile reads remain available, but the latest migration restricts profile, recipe, and storage writes to the authenticated owner and removes client writes to chef and leaderboard records (`supabase/migrations/20261026040000_secure_public_writes.sql`). The hosted project must apply that migration for these protections to take effect.
- No subscription, in-app purchase, paid plan, payment SDK, or app-side billing flow was found in `package.json` or application code. README's AdMob assertion is inconsistent with the code; confirm whether ads are planned or actually shipped before publication.
- There are no code-enforced usage quotas for creating recipes, pantry items or account access. The Edge Function enforces a 30-request hourly limit per authenticated Supabase user and caps each response at 3,200 tokens (`supabase/functions/openrouter-completion/index.ts`, `supabase/migrations/20261026040000_secure_public_writes.sql`). Because anonymous sign-up is supported, this is an account-level control rather than a strong abuse-proof global quota. OpenRouter may impose separate provider limits.
- No user-facing delete account/data, export, or consent management workflow was found. A Supabase SQL policy allows a user to delete their own `chef_app_state` row, but there is no app call/UI for it (`supabase/migrations/20261026030000_private_app_state.sql` lines 28–31). Auth deletion and removal of public recipes/profile/storage/leaderboard rows require a designed process outside what this app currently implements.
- No in-app moderation, content report, or appeal flow was found. No explicit suspension/termination mechanism exists in app code beyond inability to use the service or platform/provider enforcement.

## Matters that code cannot decide

The code alone cannot establish: contracting legal entity and any trading name; contact address and privacy contact; effective date; governing law/forum; minimum age/parental consent; service territory and target audience; user-content ownership/license scope; acceptable-use and moderation approach; whether ads are actually planned; paid features/refunds (none currently implemented); warranty/liability/indemnity posture; dispute handling; retention/deletion timelines and request process; hosting locations and processor/vendor terms; privacy rights/contact process; push-token use beyond device registration; and breach/complaint contact. Zimbabwe's Cyber and Data Protection Act is an official legal framework and current applicability should be evaluated by qualified counsel; this audit does not determine the app operator's statutory status or compliance. See [POTRAZ-hosted Act](https://www.potraz.gov.zw/wp-content/uploads/2022/02/Data-Protection-Act-5-of-2021.pdf).

## Operational items to review

1. Confirm operator/legal entity, address, support and privacy email, jurisdiction and dispute forum.
2. Confirm target ages and whether children may use the app.
3. Confirm ownership/license for user-submitted recipes and whether public recipe/image publication is the intended default.
4. Decide retention periods and an actual account/data deletion process, including public records, storage images, Auth, and anonymous state.
5. Confirm if ads, paid features or refunds exist in any production build; the checked code currently shows none.
6. Confirm actual Supabase project settings, hosting region, backup retention, OpenRouter provider routing/logging/training settings, and Expo notification token handling.
7. Apply the owner-only write migration and deploy the authenticated AI function with its server-side key before production.

## Audit scope

This audit is based on the checked repository, not the deployed backend or vendor account settings. Verify live configuration and keep the in-app Terms and Privacy Policy aligned with actual provider settings and product behavior.
